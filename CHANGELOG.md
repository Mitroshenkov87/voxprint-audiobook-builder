# Changelog

All notable changes to Voxprint. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).
The first pre-release is v0.1.0-beta; everything below is the history of the 0.1.0 development line.

## [Unreleased]

### Added
- **Code audit** (`tools/audit.py`, `requirements-audit.txt`, manual `audit` workflow, weekly CodeQL, Dependabot): one summary of ruff / mypy / bandit / pip-audit / vulture / radon / coverage. Findings fixed in the same batch: unused code and variables, a dead compatibility alias, reviewed false positives annotated; `setuptools>=78.1.1` (PYSEC-2025-49). Runtime updates now delete the files the new version no longer has (`online_fetch.run(prune=True)`, `voxprint-files.json`, runtime folder only). Docs: [docs/TESTING.md](docs/TESTING.md).
- **Component updates in the Components window** (`infra/modules.py`, `ui/modules_dialog.py`): a runtime module installed from an older manifest (same component ids, other SHA-256) is listed as an update with the installed and available versions, and Download fetches it together with any missing required module. Texts in en/ru/de. Tests: `tests/test_thin_modules.py`.
- **Quick network probe before downloads** (`infra/netroute.pick_fastest`, `tools/online_fetch.ranked`): the installer / Components downloads first fetch 256 KB through every network route in parallel (at most 4 s) and use the fastest (remembered; the others remain the fallback), and rank several sources of a component by the same short ranged GET. Only with the *Auto* network setting. Tests: `tests/test_netroute.py`.
- **Pinned vs latest components with fallback** (`tools/online_fetch.run_channel`, `infra/modules.py`): installs use the release's pinned manifest by default and fall back to the newest release's manifest when a pinned file fails or its SHA-256 does not match; the optional "Try the latest component versions" (installer checkbox / `/Latest=1`, Components window check box) tries the latest manifest first and falls back to the pinned one. A manifest is always used as a whole; runtime modules are picked by module id. See [docs/THIN-INSTALLER.md](docs/THIN-INSTALLER.md). Texts in en/ru/de. Tests: `tests/test_thin_modules.py`.
- **Start-up splash screen** (`ui/splash.py`, artwork `assets/splash.jpg` - the author's own, 720x720, 77 KB): a square splash (about 480 logical pixels, smaller on a small work area, rendered at the screen's scale) appears right after the Qt application starts, before the heavy UI modules are imported; a translucent strip at the bottom shows the product name, version, a thin progress bar and the status ("Loading interface...", "Checking components..."). It closes when the Studio window is shown. Texts in en/ru/de.
- **Small high-DPI screens (e.g. 16:10 laptops at 150 %: 1707x1027 logical pixels without the taskbar)** (`ui/screen_fit.py`): every window and dialog is sized from the screen's work area, clamped to it and centred, and re-checked when shown, so nothing opens off-screen. Height-first layouts: the Narrate cards flow into two columns when the window is wide enough (the window widens to it when the screen allows), the Train window folds its check and clip options away, Settings is a scrollable two-column dialog; tighter margins and spacing. Soft blue / yellow palette (yellow main buttons, soft blue menus and lists) on the existing dark / Acrylic theme. Settings -> *Window transparency*: default / more (~25 % more see-through) / off (`infra/ui_prefs.py`). Texts in en/ru/de. Tests: `tests/test_screen_fit.py`.
- **Voice strength (LoRA adapter scale at inference)** (`core/adapter_strength.py`): the adapter's contribution is multiplied by a per-voice strength stored in `voice.json` (`adapter_scale`, 0.10-1.00). New voices get 0.50 (research range 0.3-0.5 for fine-tuned Qwen3-TTS voices; Voxprint trains with alpha / r = 4, i.e. "louder" adapters); voices without the field keep 1.00, so they sound exactly as before. The quick preview synthesizes every variant at 0.35 / 0.50 / 1.00 on one unmerged engine (`Qwen3AdapterEngine(merge=False)`, `set_adapter_scale`, `switch_adapter`), pre-selects the best-checking strength, and a selector in each row switches the sample and its metrics; *Use these settings* stores the strength with the trained voice. The voice Properties dialog edits it. The narration cache key includes the strength (only when it is not 1.00, so old caches stay valid), the post-training check and the universal model (merged at the voice's strength, recorded in `voxprint_voice.json`) use it too. Texts in en/ru/de. Defaults need validation on a GPU ([docs/VOICE-QUALITY.md](docs/VOICE-QUALITY.md)). Tests: `tests/test_adapter_strength.py`.
- **Speaker similarity and predicted MOS in the automatic voice check** (`core/voice_check.py`, `core/mos.py`, `infra/quality_models.py`): the quick preview and the post-training check now also report (a) the similarity of the sample to your voice - cosine of Qwen3-TTS's own speaker-encoder embeddings (no extra model; the encoder the LoRA does not touch), and (b) a predicted MOS from DNSMOS P.835 (overall score, CPU, one onnxruntime thread), plus the character error rate next to the WER. Low similarity (< 0.65) or MOS (< 2.6) only adds a warning with a suggestion; the thresholds are first guesses to validate on a GPU. New download: `sig_bak_ovr.onnx` (1.16 MB, SHA-256 pinned; microsoft/DNS-Challenge at a fixed commit, Hugging Face mirror as fallback; CC BY 4.0 model, MIT reference code - see `NOTICE`, `THIRD_PARTY_NOTICES.md`), fetched with the Components "download all" step and the first-run model download, never by the check itself (`VOXPRINT_NO_MOS=1` switches it off). Texts in en/ru/de. Tests: `tests/test_voice_check_extras.py`.
- **Averaged speaker embedding over clean clips** (`core/speaker_centroid.py`): training now conditions on the centroid of up to 64 clean clips (3-15 s, no clipping, cleanest first; at least 4) instead of the single `ref.wav` embedding, and stores it as `speaker_centroid.safetensors` next to the adapter. Narration replaces the voice-clone prompt's x-vector with it (the ICL reference audio and text stay), the universal model writes it into its speaker row, the voice check compares against it, and the cache key marks it. Voices without the file (all older voices) keep the old path; `VOXPRINT_SPEAKER_CENTROID=0` switches it off. The file is kept by import / export / voice packages. Tests: `tests/test_speaker_centroid.py`.
- **Automatic pick of the best checkpoint and voice strength** (`core/checkpoint_pick.py`; Train window check box, on by default): training holds out ~5 % of the clips (validation loss per epoch in `checkpoints/losses.json`), then the last 3 epochs x strengths 0.35 / 0.50 / 1.00 synthesize up to 4 of the unseen sentences and are scored by the ASR character error rate, speaker similarity and predicted MOS (a sample that never stops is penalised). The winner's adapter and strength are kept (`checkpoints/pick.json` has every score), the other checkpoints are deleted. A strength chosen in the quick preview is respected; a failed pick only warns and keeps the last epoch. Texts in en/ru/de. Tests: `tests/test_checkpoint_pick.py`.
- **Warmup + cosine learning-rate schedule** (`core/lora_trainer.lr_factor`, `TrainPlan.lr_schedule`, default on): linear warmup over the first 10 % of the optimizer steps, cosine decay to 10 % of the peak; `"constant"` (or `VOXPRINT_LR_SCHEDULE=constant`) restores the old behaviour. The schedule and the first / peak / last learning rate are recorded in `checkpoints/losses.json`.
- **Opt-in fix for the sub-talker label double shift** (`core/lora_trainer.sub_talker_loss`; `TrainPlan.fix_sub_talker_shift` / `VOXPRINT_FIX_SUBTALKER_SHIFT=1`, default off): the library's sub-talker loss shifts the already aligned labels again (code group k+2 instead of k+1, the last group untrained; confirmed by a test). Prepared for a GPU A/B (procedure in [docs/VOICE-QUALITY.md](docs/VOICE-QUALITY.md)), not enabled. Tests: `tests/test_lr_schedule_and_subtalker.py`.
- **Qwen3-ASR-1.7B speech recognition on GPUs with ~8 GB of VRAM** (`infra/asr_choice.py`): the download-all step (first run, Components step 2, `--prefetch`, the setup folder) now fetches Qwen3-ASR-1.7B (Apache-2.0, 4.70 GB, pinned revision `7278e1e7`, every file checked by size + SHA-256) instead of the 0.6B model when CUDA reports at least 7.5 GiB; weaker GPUs and the CPU keep Qwen3-ASR-0.6B. Settings -> *Speech recognition model* overrides it (automatic / 0.6B / 1.7B / download both); a missing model is fetched right away by the download-all step, and until then the installed variant is used. `infra/model_mirrors.json` accepts *hashes-only* entries (no backup mirror) for it. Installer and manual size estimates: up to about 12 GB of models.
- **Dataset clips cross-checked by speech recognition** (`core/clip_check.py`; Train window check box with a 10-15 % threshold, on by default at 12 %): in the audio + text mode every clip is re-read by Qwen3-ASR after the quality filter and dropped when its character error rate against its text is above the threshold (slips, skipped / repeated words, alignment errors); the recognised text is normalised like the script first. The dataset never shrinks below 20 clips because of the check (the worst go first, a warning names the doubtful ones kept); the result names how many clips were dropped and `report.json` lists them. The aligner is unloaded before the recogniser loads; no installed recogniser = the check is skipped with a warning. Not used for the quick preview and for auto-transcribed datasets.
- **Every narrated chunk checked by speech recognition** (`core/chunk_check.py`; Narrate window check box, switched on by the *High* quality preset, off otherwise): after each synthesized batch, every new chunk is re-read by Qwen3-ASR (0.6B when installed) and generated again when its character error rate against its text is above 15 % - up to 2 retries with temperature 0.8 / top_p 0.85 / top_k 30 and a seed derived from the chunk's cache key and attempt (reproducible) - keeping the best attempt (`Qwen3AdapterEngine.synthesize_sampled`). The check runs before the chunk is written, so the cache key, resumed jobs and the CPU overlap of chapter assembly / encodes are unchanged; cached chunks are never checked again. The recogniser loads after the TTS model, goes to the GPU only with 2 GB of VRAM to spare (else the CPU) and is unloaded when synthesis ends; no installed recogniser = no check. The finished job reports how many chunks were regenerated. Texts in en/ru/de. Tests: `tests/test_chunk_check.py`.
- **Longer training clips** (`core/slicer.long_clip_config`; Train window "Longest training clip", 12-20 s, default 15 s): in the audio + text mode long sentences with commas are kept whole up to the chosen length instead of being cut mid-sentence (gentler length cost above the 8 s target for segments that end a sentence), so most clips stay near 8 s and a share becomes 12-20 s. GPUs with less than 10 GB and the CPU are capped at 15 s (`infra/vram_optimizer.safe_max_clip_seconds`; training stays batch 1); 12 s gives exactly the old cut. `report.json` records `max_clip_seconds` and `segments_over_12s`. Texts in en/ru/de. Tests: `tests/test_long_clips.py`.
- **Optional noise clean-up for noisy recordings** (`core/denoise.py`, `infra/denoise_tool.py`; off by default): when the DNSMOS background score of the chosen recording(s) is below 3.0, the Train window offers an unticked "Clean up background noise before training (DeepFilterNet3)" check box and a separate download button. The tool is the `deep-filter` 0.5.6 program of DeepFilterNet (MIT OR Apache-2.0, model embedded, CPU; Windows x64 26.9 MB `75e11fa1...`, Linux x64 36.4 MB `70775e25...`, pinned by size + SHA-256), never fetched by the "download all" step or silently. A cleaned 48 kHz copy (attenuation limit 30 dB) in `<job>/denoised/` is used for training; the original is untouched, a failure falls back to it with a warning. MossFormer2 and Sidon were checked and not used (heavier). `NOTICE`, credits and `THIRD_PARTY_NOTICES.md` updated. Texts in en/ru/de. Tests: `tests/test_denoise.py`.
- **Logging and diagnostic report** (`infra/diagnostics.py`): one rotating log `logs/voxprint.log` in the data folder (5 MB x 6 files, ~30 MB cap; was 2 MB x 4) with uncaught exceptions of the main and worker threads, Qt messages and Python warnings (with tracebacks); a start-up block (version, OS, Python, CPU cores, RAM, GPU / driver / CUDA / VRAM; settings with paths cut to names and secrets dropped); model loads (device, time, VRAM after), downloads (source, MB/s, hash result), training (loss + learning rate per epoch, peak VRAM, duration, checkpoint-pick scores and winner), dataset clip-check drops, narration (chunks, chunk-check retries, stage timings, each encode), noise clean-up decisions and every task warning. Settings -> **Save diagnostic report...** and the CLI `diag` command zip the logs with `system_info.json` and `settings.json`. Texts in en/ru/de. Docs: FAQ, CLI. Tests: `tests/test_diagnostics.py`.
- **Literary translation and "Prepare text for narration" (optional AI model)** (`core/llm_text.py`, `infra/llm_tool.py`, `prompts/`): Gemma 4 12B Instruct (Apache-2.0, GGUF Q4_K_M 7.1 GB, pinned revision + SHA-256) in llama.cpp's `llama-server` (MIT, Vulkan build b11476, ~33 MB) as a separate, user-started download (not in download-all; greyed out until downloaded and below ~10 GB of VRAM). Paragraph-level translation with context and a names glossary, or a same-language rewrite for listening; a guard (paragraph / line count, length ratio, language, refusals) sends failed paragraphs to Opus-MT (or keeps the original). The model process ends before the voice model loads. Prompts are editable text files. Off by default.
- **Re-voice** (`core/revoice.py`, `ui/revoice_window.py`, Studio card; docs/REVOICE.md): record from the microphone (Qt Multimedia record / stop / play) or import audio files (MP3, WAV, M4B ...; several files = chapters) -> the installed Qwen3-ASR (pieces of up to 25 s cut at pauses) -> editable text (`# Chapter` lines) -> the normal narrator with any voice. No new models.
- **Direct voice conversion (Re-voice phase 2): evaluated, not included** (docs/REVOICE.md): OpenVoice V2 is the only candidate with MIT code and weights, but it needs vendored model code and a second audio pipeline and converts only the timbre; Seed-VC (GPL-3.0), EZ-VC (non-commercial weights) and RVC (per-voice training) do not fit.

### Changed
- **Translator: Opus-MT tc-big models** (`infra/text_models.py`, `core/translate.py`): en->ru, ru->en, ru->de and de->ru now use Helsinki-NLP `opus-mt-tc-big-en-zle`, `-zle-en`, `-zle-de`, `-de-zle` (CC-BY-4.0, ~480 MB each, safetensors only, pinned revision + SHA-256 of every file; `>>rus<<` target token for the multi-target models). Russian <-> German is translated directly instead of through English. en<->de keeps `opus-mt-de-en` / `-en-de` (no tc-big model for that pair). All six translator models are part of the download-all step (Components step 1, first-run prefetch of full builds; ~2.5 GB more). Installs that already have the 2020 `opus-mt-ru-en` / `-en-ru` keep using them as a fallback until the tc-big model of that direction is present. Size estimates updated (models up to ~15 GB).
- **Narration uses the CPU while the GPU speaks** (`core/cpu_budget.py`, `core/narration.py`, `core/audiobook_export.py`): chapter WAVs are joined and per-chapter MP3 / Opus / FLAC files are encoded as soon as a chapter's chunks are cached, instead of after the whole book; the single-file formats (M4B, Opus, MP3) are encoded in parallel at the end; text normalisation runs while a fresh job loads the model. The CPU pool is sized from the physical cores (one core feeds the GPU, one or two stay with the UI / OS), ffmpeg runs at below-normal priority, torch's CPU threads are capped during GPU synthesis (restored afterwards), and pending chunk writes are bounded. Output files are byte-identical to the serial path; pause and cancel also hold the background work. Mock-GPU benchmark (`tools/bench_narration.py`, 8-core box, MP3 chapters + Opus + M4B): 50 min of audio, GPU-bound - time after the GPU finished 58.9 s -> 34.6 s (total 230.9 s -> 206.5 s); 100 min of audio on a fast GPU - total 132.0 s -> 83.3 s. The rest of the tail is the single-threaded AAC encode of the M4B. Tests: `tests/test_narration_pipeline.py`.
- **First-start download flow (thin / online installer)**: the Components window (`ui/modules_dialog.py`) no longer lists installed / not installed rows. It starts by itself on the first start and shows ONE live line naming what is downloaded right now (`Downloading: PyTorch (torch-...whl) — 42% · 35 MB/s`), then `Verifying: ... (SHA-256)`, or the error on the same line, plus an overall progress bar ("Step 1 of 2: program components", "Step 2 of 2: models"). The downloader (`tools/online_fetch.py`) reports structured download / verify / unpack events with a smoothed speed (`_Rate`); the installer's status file gets the same information as short English text.
- **SAGE comes with the components** (`infra/text_models.COMPONENT_EXTRAS`, `ensure_component_extras`): step 1 downloads the SAGE text clean-up model right after the runtime libraries, no click in the Narrate window. A failed SAGE download is not fatal: step 2 lists it again.
- **All heavy models right after the components, no "Maximum quality (auto)" button**: step 2 starts the first-run model download (`workers.pipeline_runner.prefetch_models`: TTS, aligner, Qwen3-ASR, SAGE) automatically, into the chosen models folder, with backup restore and existing copies first. The Settings button "Maximum quality (auto)" and `workers/auto_quality_worker.py` were removed (every recommended option stays pre-selected). Model progress lines now start with "Downloading:" / "Verifying:" (en/ru/de), and the overall bar is weighted by model size.

- **Narration speaks in the language of the text, not of the voice** (`core/languages.py`, `workers/narration_runner.py`): the language token passed to Qwen3-TTS `generate_voice_clone` is now the translation target when translating, else the book's language (its metadata tag, or detected once from a text sample when the tag is missing or contradicted by the text), the voice's language only as the last fallback, `Auto` if nothing is known. Any form (`ru`, `ru-RU`, `russian`, `Russian`, `русский`) is normalised to the model's exact names (Chinese, English, French, German, Italian, Japanese, Korean, Portuguese, Russian, Spanish, Auto; taken from the `qwen_tts` source). A Russian voice reading an English book now gets `English`. The cache tag includes the token only when it differs from the old behaviour, so existing chunk caches stay valid. Tests: `tests/test_narration_language.py`.

- **Voice details in `voice.json` (schema 3)** (`core/voice_info.py`): new optional fields `speaker`, `prepared_by`, `organization`, `project_url` (http/https only, cleaned like `license_url`), `gender` (`male|female`) and `age_group` (`child|young|adult|elderly`); text fields accept any script (only folder names stay Latin). `language` is stored as a BCP-47 code (`ru`, `en`, `pt-BR` ...), `created` stays ISO 8601 UTC. Older files are migrated when read: `voice_type` male/female -> `gender`, child -> `age_group`, language names -> codes. `voice_type` is still written, derived from gender / age group, so folder suffixes (`anna_female`), the catalog and older app versions keep working. The Train window has gender and age selectors plus a folded "More about the voice" section; the voice Properties dialog edits all fields in a compact form (en/ru/de). `tools/make_voice_package.py` puts the new fields into the index entry and writes a Hugging Face model card (`README.md`, YAML metadata + table); the voices index reader and the download keep them. `voices list` (CLI) adds gender and age-group columns. Tests in `tests/test_voice_info.py`, `tests/test_voice_catalog.py`.

### Fixed

- **First-run download-all includes ASR and SAGE** (and verifies every finished download by size + SHA-256 against `infra/model_mirrors.json` before marking it ready). Previously Qwen3-ASR and sage-fredt5 were fetched silently later by the voice check / A/B / spoken consent (or on narrate prep paths); those features now use the already-fetched local copy and skip WER / fall back clearly when the model is missing. Portable setup `models=auto` also keeps SAGE. Tests: `tests/test_download_verify.py`.
- **A finished model download was marked done after a structural check only.** Downloads from Hugging Face / ModelScope were renamed into place once `config.json` and a weights file existed; a truncated or corrupt file could pass. Now every file of the pinned revision is checked by size + SHA-256 against `infra/model_mirrors.json` before the rename (`model_downloader.manifest_bad_files`; git metadata and pictures are ignored). Bad files are deleted and re-fetched from the hash-verified backup mirror when it is available; otherwise the download fails with the integrity message and the `.partial` folder keeps the good files so the next attempt fetches only the missing ones. The GitHub-release and mirror paths already verified every file. Each download now also logs who requested it (`download of X requested by ...`) to explain unexpected downloads. Tests: `tests/test_download_verify.py`.
- **A Voxprint backup chosen as the "Models folder" became the live models folder.** Picking a `Voxprint-backup` folder (with `voxprint-backup.json`, `models/`, `voices/`) on the installer page bound the program to that path (often an external drive) and, because the backup layout is not a models folder, the models were downloaded again into it. Now the rule is hybrid: an empty or normal folder is still the download target; a backup (detected by `infra/paths.py: backup_root_of` and the installer's `BackupRootOf`) is a **restore source** - stored as the existing-models folder, restored once (models, voices, ffmpeg; hash-verified) into the normal folders on the first start (`infra/existing_models.py: adopt_backup_choice / restore_backup`, hooked into the first-run step and `ensure_model`), and `models_dir` never points at a backup. An older `models_dir.txt` that points at a backup is converted on start. Installer page text updated (en/ru/de) plus a notice when a backup is found; takes effect with the next installer build (the app-side conversion works with the current installer). A `Voxprint-backup` folder whose manifest is missing is recognised too (imported model by model); a failed restore does not loop on every model / every start. Tests: `tests/test_backup_as_models_source.py`, `tests/test_installer_models_page.py`.
- **The download line "N MB of TOTAL" and the time jumped.** Causes: the total was the sum of the progress bars that Hugging Face opens file by file (it grew while the download ran); for ModelScope and the backup mirror it was guessed as `done / fraction` (a fraction that moves per file); every source switch started a new meter (counter, total, speed from zero); the speed reacted to every burst. Now ONE meter serves the whole model: the total is the sum of file sizes known up front (pinned sizes, release / mirror manifest, Hugging Face API, ModelScope file list; without it only the downloaded size is shown), the counter and the bar never go back, the speed is a moving average, the time left appears after 6 s and is kept steady, and the current source is shown. Tests: `tests/test_download_progress.py`.

### Changed
- **Download order.** Small models (up to 500 MB: Opus-MT x4, SAGE; 1.6 GB) come first from the GitHub pre-release `models-v1` (`infra/model_release.py`, `infra/model_release.json`, `tools/make_model_release.py`), then original Hugging Face -> our Hugging Face mirror -> ModelScope. Large models: original -> our mirror -> ModelScope (ModelScope first when Hugging Face is slow). See [docs/MODELS.md](docs/MODELS.md). Tests: `tests/test_model_release.py`.

- **A downloaded model could not be finished on Windows (`PermissionError WinError 5` on `<model>.partial` -> `<model>`) and was downloaded again in a loop** (found on a real PC). `ensure_model` now (1) recognises a `.partial` folder that already holds every file of the pinned revision (sizes) and only finishes it, without any network access; (2) finishes with `finalize_download`: closes our own handles, removes the hub's `.cache` lock files, renames with up to 10 retries and back-off (~30 s), clears read-only attributes, logs which processes have files open there (psutil) and, if Windows still refuses, copies the folder; the error then says that nothing has to be downloaded again; (3) the stall watchdog does not count "all files are present" as a stall; (4) "Hugging Face is slow" is remembered only after a real network failure (timeout, reset, DNS, stall), never after a disk / permission error. **One download per model across processes**: `ModelLock` (OS file lock `models/.<name>.lock`, released by the OS if a process dies) - the background quality worker and the prefetch no longer download and rename the same model in parallel; the second waits ("another Voxprint process is downloading this model") and then finds it finished. Tests: `tests/test_download_watch.py`.
- **Closing the main window ends everything at once** (`infra/hard_exit.py`): all child and grandchild processes are killed (psutil, `/proc` or `taskkill /T`) and the process exits without waiting for threads; on Windows the process also sits in a kill-on-close job object, so helpers die even if the main process is killed. Armed only by `main.py` in a real run (not in `--selftest*` or tests). Programs the user opened from Voxprint (e.g. an audio player started with *Open*) are children too and are closed with it. Tests: `tests/test_hard_exit.py`.
- Script matching (`core/script_match.py`) now also stops at a consent header written `CONSENT` or `EINWILLIGUNG` (any case), not only `СОГЛАСИЕ`. Test in `tests/test_script_match.py`.
- Consent statement: the name and the date written in words by the recogniser ("третьего октября две тысячи двадцать шестого года", no commas) are now read (`core/spoken_date.py`, ru/en/de) - found with real Qwen3-ASR output on an RTX 4090.
